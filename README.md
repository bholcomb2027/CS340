# CS340
Project Reflection: Grazioso Salvare Dashboard
Writing Maintainable, Readable, and Adaptable Programs
I made the dashboard easier to maintain by separating database operations from the dashboard code. The CRUD Python module handles communication with MongoDB, while the dashboard uses that module to retrieve records and display them. This separation gives each part a clear responsibility: database logic stays in the CRUD module, and the interface and its callbacks stay in the dashboard.
Using descriptive names, comments, and consistent formatting also makes the code easier to understand. For example, the filter queries are grouped by rescue type, and the dashboard callbacks each handle a specific interaction. If the database connection or query logic needs to change, it can be updated in the CRUD module without rewriting the dashboard components that display the results.
The CRUD module is reusable beyond this project. It could support another dashboard, a command-line tool, or a different application that needs to create, read, update, or delete animal records. It could also be adapted to support another shelter or organization by changing the database configuration and queries while keeping the core database methods.
Problem-Solving Approach
I approached the project by breaking the client’s requirements into smaller tasks: connect to MongoDB, retrieve the animal records, create the dashboard controls, write queries for each rescue profile, and connect the results to the table, map, and chart. I compared the filter criteria against the specifications and tested each option, including Reset, to check that the displayed data changed as expected.
This project required me to consider how multiple parts of an application work together. In some earlier assignments, I focused on solving a smaller programming problem within one file or function. Here, I needed to think about the database, Python module, dashboard interface, callbacks, and user experience as parts of one system. Testing the full workflow was important because a query can be correct on its own but still cause problems when its results are passed to a dashboard component.
For future database projects, I would begin by clarifying the client’s needs and identifying the data fields and operations the application requires. I would examine the data for missing or inconsistent values, design queries around the client’s actual use cases, and keep database access separate from the user interface. I would also test normal cases, empty results, and unusual records, then use error messages and logs to diagnose problems rather than relying only on whether the interface appears to work.
The Role and Value of Computer Science
Computer scientists use computing principles to design and build systems that solve practical problems. Their work can involve understanding a client’s needs, organizing data, developing software, testing it, and improving it so that people can use it reliably.
This project shows how software can help Grazioso Salvare make better use of animal shelter data. Rather than manually searching through records, users can filter animals by rescue type and review relevant details in a table. The map and chart provide additional ways to inspect the results. A clear, interactive dashboard can reduce repetitive work and make it easier for staff to find animals that match the organization’s training criteria.
The work matters because well-designed software helps people spend less time managing information and more time acting on it. By connecting the database to an accessible interface, this project gives users a practical way to explore shelter records and support the organization’s rescue-animal selection process.
